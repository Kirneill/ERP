Executive summary

I would frame the project like this: this is a focused ERP integration and project controls demo for AEC teams. It does not try to replace a full ERP. It shows how I connect project health, imported time entries, validation errors, audit history, and reporting evidence into one inspectable workflow.

.NET API React/Vite SQLite/EF Core reset endpoint

Business problem

AEC project leaders need one operational view that answers which projects need attention and why. Budget drift, schedule variance, and integration errors usually live in different places. This demo turns those signals into health bands, exception lists, and audit history.

Interviewer prompt

What would a project executive or project manager want to know in the first minute?

Candidate answer

I would show the health table, the at-risk panel, and the recent integration errors before I talk about implementation details.

Validation and data integrity

The sample import contains five rows: 2 accepted and 3 rejected. The rejected sample cases cover negative hours, missing work date, and excessive daily hours. The broader validator also rejects unknown projects, unknown employees, missing external references, duplicate references, and null rows.

  • Hours must be greater than zero and less than or equal to 24.
  • Work date must be present and parseable.
  • Project and employee references must match seeded records.
  • External references are required and checked for duplicate submissions.

Error logging and audit traceability

Rejected rows

Rejected rows are persisted as integration errors with source system, operation, severity, message, project number, employee number, external reference, timestamp, and details.

Accepted rows

Accepted rows become time entries and create audit log records. Import batch completion also creates audit evidence with accepted and rejected counts.

The frontend includes an exception report CSV action. It downloads integration-exception-report.csv with source system, event type, status, project, external reference, message, and timestamp columns.

SQL implementation evidence

Project health is exposed through a reporting-style SQLite view named vw_project_health, mapped by EF Core as a keyless view. This is the strongest database talking point for ERP reporting, BI, and integration discussions.

CREATE VIEW vw_project_health AS
SELECT
  p.Id AS ProjectId,
  p.ProjectNumber,
  p.Name,
  c.Name AS ClientName,
  c.MarketSector,
  p.ContractValue,
  p.EstimatedCostAtCompletion,
  ROUND((p.EstimatedCostAtCompletion * 100.0) / p.ContractValue, 2) AS BudgetUtilizationPercent,
  CAST(julianday(date(p.ForecastEndDate)) - julianday(date(p.PlannedEndDate)) AS INTEGER) AS ScheduleVarianceDays,
  CASE
    WHEN p.ContractValue <= 0 OR p.EstimatedCostAtCompletion > p.ContractValue THEN 'RED'
    WHEN ((p.EstimatedCostAtCompletion * 100.0) / p.ContractValue) < 75 THEN 'GREEN'
    WHEN ((p.EstimatedCostAtCompletion * 100.0) / p.ContractValue) < 90 THEN 'YELLOW'
    ELSE 'RED'
  END AS RiskStatus
FROM Projects p
INNER JOIN Clients c ON c.Id = p.ClientId;

Production roadmap

  • Add authentication, SSO, RBAC, tenant isolation, secure secrets, and production-grade audit retention.
  • Replace the local sample import with real ERP, timekeeping, Procore, Autodesk, Deltek, Sage, or accounting connectors.
  • Move SQLite to managed production storage with migrations, backups, observability, and deployment automation.
  • Add background job handling, retry policies, dead-letter workflows, and alerting for failed integration batches.
  • Expand automated coverage with end-to-end browser checks and accessibility audits before release.

60-second talk track

This is a focused ERP-adjacent integration slice for AEC project operations. It shows how I translate disconnected project controls and integration errors into a working demo. The React/Vite dashboard calls a .NET Minimal API backed by SQLite and EF Core. Project health comes from the vw_project_health SQL view and service scoring. The sample import sends five time-entry rows: two are accepted and three are rejected. Accepted rows create audit logs, rejected rows become visible integration errors, and those errors can be downloaded as an exception report CSV. A reset endpoint returns the local demo to a known state. For production, I would add auth, RBAC, real connectors, monitoring, stronger audit controls, and deployment automation.
